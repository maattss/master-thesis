\section{Game Description}
\label{chap:game_description}
In this chapter, a descriptive overview and screenshots from the mobile application will be presented. Figure \ref{fig:nav_bar} shows the bottom navigation bar in Hover, displaying the five main screens: Feed, Challenge, Hover, Leaderboard, and Profile. Additionally, there are signup and login screens in which unauthenticated users are faced when they open the application. We will start by describing the signup and login screens before continuing with the description of the five main screens.

\subsection{Sign Up and Login}
The first time a user opens the application, they are presented with a login screen as seen in Figure \ref{fig:login}. If the person does not have an account, they can navigate to the signup screen and create a new one. The user needs to select their chosen avatar, preferred username, and password to sign up. When they are satisfied with their selection, a new user is created by clicking the “Sign up” button, shown in Figure \ref{fig:signup}. The login and signup screens are both developed based on the first functional requirement (\textbf{FR1}), which states, \textit{“The user should be able to create an account and log in.”}

The feed is the first of five main screens. It is used to showcase posts of new activities, earned achievements, and completed challenges for all users in the application. A screenshot of the feed is shown in Figure \ref{fig:feed}. At the top, Conrad’s newly published activity, where he has been at “Studentersamfundet” in Trondheim together with Tomine, is shown. Below Bjørn’s new “1000 points in total,” bronze achievement is displayed. The bottom post announces Tarzan as the winner of a challenge against Kimmy, Herman, and Morten.

The user can also show their tribute to elements in the feed by pressing the “clap emoji.” We see that in this figure, the user has reacted to Tarzan’s challenge win.

\subsubsection{Notifications}
A closer look at the top right corner of the feed screenshot (Figure \ref{fig:feed}) reveals a notification icon with a badge illustrating two new notifications. When pressing this button, the user will be directed to the notifications page. 

As seen in Figure \ref{fig:notifications} this screen gives an overview of all notifications, where unread ones are listed at the top, and earlier ones are displayed below. Pressing the various items redirects the user to a specific part of the application relevant to the type of notification.
